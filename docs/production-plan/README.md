# HTMZ Kit — دراسة الجدوى المستقلة وخطة الإنتاج

> **القرار: CONDITIONAL GO.** الفكرة تستحق الاستثمار، لكن آلية النقل الحالية (الإطار المخفي) يجب استبدالها بطبقة Fetch اختيارية فوق تطبيق صفحات كاملة. التفاصيل في الوثيقتين 04 و10.
>
> هذه وثائق تخطيط وتقييم فقط. لم يُنفَّذ أي جزء من الخطة، ولم يُعدَّل أي كود مصدري. التاريخ: 2026-11-05. الفرع: `docs/htmz-production-feasibility-plan` المتفرع من `feat/backend-agnostic-design-system` عند الالتزام `66d4de6`.

## الملخص التنفيذي

1. **htmz الأصلي** تجربة أنيقة مكتملة (168 بايت) لكنها ليست منتجًا ولا تُصان. قيودها قياسية لا تنفيذية.
2. **عمل ChatGPT السابق** صادق في أرقامه (57/57، 108/108، 6/6 أُعيد إنتاجها مستقلًا) ومبالغ في توصيفه («نظام تصميم»، «Backend Agnostic»، «Mobile-First»).
3. **ثبت بفحوص مستقلة جديدة** أن الإطار المخفي: لا يعمل بلا JavaScript (المستخدم لا يرى شيئًا)، ويجعل زر الرجوع يغيّر المحتوى دون العنوان، ويعرض أجزاء عارية عند فتح الرابط مباشرة، وأن `Origin: null` في الخادمين سببه `Referrer-Policy` لا الإطار.
4. **منصة الويب في 2026** تغطي كل ما يحتاجه نظام تصميم وتفاعلات تطبيق أعمال دون بناء ودون مكتبات: `@layer`، Container Queries، Nesting، الخصائص المنطقية، `<dialog>`، `popover`، `<details name>`، `:user-invalid`، Fetch، DOMParser، History.
5. **المعمارية الموصى بها:** صفحات كاملة من الخادم + ملف JavaScript اختياري واحد ≤ 5 كيلوبايت + نظام تصميم CSS عربي أولًا Mobile-First + عقد خادم بسيط + خادمان مرجعيان + مولّد + اختبارات ثلاثية المحركات.
6. **الجهد:** 16–24 أسبوع عمل هندسي بست مراحل وخمس بوابات GO/NO-GO. **MVP:** 12–18 أسبوعًا.
7. **ما يُستبعد عمدًا:** المصادقة، ORM، النشر، مكوّنات JavaScript، بلا اتصال، اللحظي، أي خطوة بناء.

## تعريف «صفر تبعيات» المعتمد

| المستوى | الالتزام | الحالة في المنتج المقترح |
|---|---|---|
| 1. لا JavaScript من طرف ثالث في المتصفح | **ملزم** | ملف واحد نملكه، اختياري |
| 2. لا خطوة بناء إلزامية | **ملزم** | CSS وJS تُكتب كما تُشحن |
| 3. لا مدير حزم إلزامي للواجهة | **ملزم** | `npm` للاختبار فقط |
| 4. لا مُجمِّع ولا مُصرِّف للواجهة | **ملزم** | — |
| 5. لا لغة مكوّنات مخصصة | **ملزم** | HTML + سمة `data-target` واحدة |
| 6. لا JavaScript إلزامي للوظائف القياسية | **ملزم** | كل شيء يعمل بصفحات كاملة |
| 7. أدوات اختبار للتطوير فقط | **مسموح** | Playwright، axe-core (اختياري)، مثبتة الإصدار |
| 8. بيئة تشغيل الخادم وقاعدة البيانات | **حتمية ولا تُحسب على العدة** | أي خادم يُخرج HTML |

الادعاء الصادق: **«بلا تبعيات واجهة وبلا بناء»**، لا «بلا تبعيات».

## تعريف المنتج المستهدف (HTMZ Kit — الاسم مؤقت)

| البند | التعريف |
|---|---|
| الغرض | أساس لبناء تطبيقات أعمال محترفة بـ HTML وCSS أصليين من أي خادم، عربية أولًا، Mobile-First، بلا بناء |
| المستخدمون | مطورو الخلفية والفرق الصغيرة والمؤسسات العربية والبيئات المقيدة |
| المبادئ | كل عنوان صفحة كاملة؛ الرابط رابط والنموذج نموذج؛ طبقة تحسين واحدة اختيارية؛ الخادم مصدر الحقيقة؛ لا تنفيذ لسكربتات الاستجابة؛ سمة مخصصة واحدة فقط |
| خط الأساس | Chrome/Edge 120، Firefox 128 ESR، Safari/iOS 17.2 (الوثيقة 03 §1) |
| القدرات الأصلية المطلوبة | Forms، `<dialog>`، `popover`، `<details name>`، `:user-invalid`، `@layer`، Container Queries، Nesting، الخصائص المنطقية، Fetch، AbortSignal.timeout، DOMParser، History |
| التحسينات الاختيارية | View Transitions، `light-dark()`، `@starting-style`، Invoker Commands، Speculation Rules |
| عقد HTML/الخادم | الوثيقة 04 §4.2 |
| عقد نظام التصميم | الوثيقة 05 |
| سير عمل المطور | اكتب HTML دلاليًا → طبّق أصناف `ds-*` → نفّذ المسارات في خادمك وأعد HTML → شغّل؛ أضف `data-target` حيث يفيد التحديث الجزئي فعلًا |
| المولّد | ينسخ العدة إلى مجلد جديد ويخصص الاسم؛ لا يثبّت شيئًا ولا يكتب فوق شيء |
| الاختبار | Playwright في ثلاثة محركات + خادمان + axe + لقطات + سيناريو بلا JavaScript؛ أجهزة حقيقية قبل الإصدار |
| حدود الأمان | الوثيقة 07 §1 |
| تكامل الإنتاج | دليل نشر خلف وكيل عكسي + دليل تكامل مع إطار واحد على الأقل (المرحلة 5) |
