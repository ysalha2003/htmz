# 06 — خطة Mobile-First وتجربة الجوال والوصول

> الهدف: أن ينتج أي تطبيق مبني بالعدة تجربة بمستوى تطبيقات SaaS الحديثة على الهواتف الصغيرة والأجهزة اللوحية وسطح المكتب، دون تقليد تعقيد أطرها.

## 1. تقييم البنية البصرية الحالية

| البند | الحالة في Starter Kit | المطلوب |
|---|---|---|
| ترتيب الاستعلامات | Desktop-First (`max-width: 760px`) | Mobile-First (`min-width`) + `@container` |
| التنقل في الجوال | شريط علوي فقط، لا قائمة | درج أو تنقل سفلي بـ `details`/`popover` |
| الجداول | غير موجودة | نمط جدول/بطاقات حسب الحاوية |
| حد اللمس | أزرار 2.8rem (≈45px) جيدة؛ روابط التبويبات أصغر | رمز `--ds-size-touch: 44px` يُطبَّق على كل الأهداف |
| ارتفاع الشاشة | غير مستخدم | `dvh` للشاشات الكاملة والأدراج |
| الشق والحواف الآمنة | غير مستخدمة | `env(safe-area-inset-*)` مع `viewport-fit=cover` |
| تقليل الحركة | غير موجود | إلزامي |
| التركيز بعد التحديث | موجود (`data-focus-on-swap`) | يبقى ويُعمَّم |
| الإعلانات للقارئات | موجود (`role=status`) | يبقى مع سياسة نصوص موحدة |
| اختبار على أجهزة حقيقية | لا | إلزامي قبل الإصدار (قسم 6) |

الخلاصة: البنية الحالية **صالحة كنقطة بداية** لكنها ليست Mobile-First ولا تكفي لبرمجيات احترافية. ما يبقى: الرموز، الطبقات، الخصائص المنطقية، التركيز، الإعلانات. ما يتغير: الاتجاه، المكوّنات، الجوال.

## 2. مبادئ التخطيط

1. **الشاشة الضيقة هي الافتراضي.** الأنماط الأساسية تخدم 320–430px؛ الأعرض يضيف أعمدة بـ `min-width` أو `@container`.
2. **المكوّن يستجيب لحاويته لا للشاشة.** قائمة/تفاصيل تتحول إلى عمودين عندما تتجاوز حاويتها `--ds-container-md`، سواء كانت في صفحة كاملة أو لوحة جانبية.
3. **التدفق العمودي أولًا.** لا ارتفاعات ثابتة؛ `min-height: 100dvh` للهيكل فقط.
4. **إجراء أساسي واحد في متناول الإبهام.** شريط إجراءات سفلي ثابت في النماذج الطويلة.
5. **لا تمرير أفقي للصفحة أبدًا.** اختبار آلي: `scrollWidth <= innerWidth` في 320px.
6. **كثافة قابلة للتعديل:** رمزا `--ds-density` (مريح/مضغوط) يغيّران المسافات والارتفاعات دون لمس المكوّنات.

## 3. الأنماط الأساسية

| النمط | الحل |
|---|---|
| التنقل الرئيسي | جوال: شريط علوي + زر قائمة يفتح درجًا (`<details>` أو `popover`) مع `inert` للمحتوى الخلفي؛ لوحي/مكتبي: شريط جانبي ثابت عبر `@container`/`min-width` |
| القوائم والجداول | ≤ `--ds-container-md`: كل صف بطاقة بعناوين مضمّنة (`th` مخفية بصريًا + `data-label`)؛ أوسع: جدول عادي مع `overflow-x: auto` و`scroll-snap` اختياري |
| قائمة/تفاصيل | جوال: صفحتان (القائمة ثم التفاصيل، كل منهما عنوان حقيقي)؛ أوسع: عمودان مع تحديث جزئي اختياري للتفاصيل |
| النماذج | عمود واحد، حقول بعرض كامل، تسمية فوق الحقل، أخطاء تحت الحقل بـ `:user-invalid`، `inputmode` و`autocomplete` و`enterkeyhint` صحيحة، حجم خط 16px |
| البحث | `<search><form method=get>` في أعلى الصفحة، نتائج كاملة بلا JS؛ مع التحسين: استبدال منطقة النتائج |
| الفلاتر | رقائق في صف قابل للتمرير أفقيًا؛ الفلاتر المتقدمة داخل `<details>` أو حوار في الجوال |
| الحوارات | `<dialog>` بعرض كامل من الأسفل في الجوال (ورقة) ومركزي في الأعرض؛ `max-block-size: 90dvh` |
| الإشعارات | منطقة `role=status` أسفل الشاشة فوق الحافة الآمنة |
| الحالات الفارغة وحالات التحميل | قوالب موحدة؛ `aria-busy` على المنطقة أثناء الجلب |

## 4. لوحة المفاتيح والتركيز

- ترتيب DOM = ترتيب القراءة = ترتيب التبويب. لا `tabindex` موجب.
- حلقة تركيز بسماكة 3px وتباين ≥ 3:1 مع كل سطح، عبر `:focus-visible`.
- بعد كل تحديث جزئي: التركيز ينتقل إلى عنوان المنطقة (`tabindex=-1`) أو إلى أول خطأ في النموذج، مع `preventScroll` ثم `scrollIntoView` حسب تقليل الحركة.
- بعد التنقل الكامل: المتصفح يتولى الأمر؛ `autofocus` فقط في الحوارات.
- الحوارات تعيد التركيز إلى العنصر الذي فتحها (سلوك `<dialog>` الأصلي).
- رابط تخطٍّ في كل صفحة.

## 6. الأداء على الأجهزة المتواضعة

- **الميزانية لكل صفحة (هدف):** HTML ≤ 60 كيلوبايت، CSS ≤ 15 كيلوبايت مضغوطًا، JS ≤ 5 كيلوبايت مضغوطًا، لا خطوط ويب افتراضيًا، صور بـ `loading=lazy` و`width/height`.
- **مؤشرات الهدف** (تُقاس بـ Lighthouse على جهاز Moto G4 المحاكى أو ما يعادله، شبكة 4G بطيئة): LCP ≤ 2.5 ثانية، INP ≤ 200 مللي ثانية، CLS ≤ 0.1.
- **القوائم الطويلة:** ترقيم صفحات من الخادم افتراضيًا؛ `content-visibility: auto` للمحتوى الطويل كتحسين.
- **الذاكرة المؤقتة:** `Cache-Control` للملفات الثابتة بأسماء مُرقَّمة (`design.v1.css`)، والصفحات `no-store` أو `private` حسب التطبيق.
- **bfcache:** لا `unload`، لا `Cache-Control: no-store` على صفحات لا تحتاجه، لتعمل العودة الفورية.

| قارئ شاشة حقيقي (VoiceOver على iOS، TalkBack على Android، NVDA على Windows) | يدوي | قبل كل إصدار رئيسي |
| أجهزة حقيقية: iPhone متوسط العمر، Android متواضع | يدوي | قبل كل إصدار رئيسي |
| Lighthouse على محاكاة جهاز متواضع | أداة اختيارية | قبل كل إصدار |

WebKit في Playwright **ليس Safari iOS**: لا يحاكي الشريط العلوي/السفلي المتحرك ولا سلوك تكبير الحقول ولا VoiceOver. لذلك الاختبار اليدوي على iPhone حقيقي شرط إصدار لا توصية.
