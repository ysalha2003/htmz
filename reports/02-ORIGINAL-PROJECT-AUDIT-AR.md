## طريقة العمل
1. يحمل الرابط target=htmz أو النموذج target=htmz استجابة HTML داخل iframe باسم htmz.
2. يقرأ معالج onload في htmz.html قيمة iframe.contentWindow.location.hash.
3. يعامل الهاش كـ CSS selector داخل وثيقة الصفحة الأم بواسطة document.querySelector.
4. يستبدل العنصر الأول المطابق بكل childNodes الموجودة في iframe.contentDocument.body باستخدام replaceWith.
5. يستخدم setTimeout صفرًا لتأجيل التبديل وتخفيف التمرير التلقائي؛ وهذا سلوك موثق بالمصدر.
6. لا يوجد fetch ولا AJAX ولا hydration ولا virtual DOM ولا مكتبات تشغيل.

تتضمن الشجرة docs وexamples (HTML/PHP/Node/Cloudflare) وامتدادات اختيارية مثل loader وmultitarget وno-history وrepeat-gets وswap-template وunwrap-template. النسختان htmz.html المختصرة وhtmz.dev.html المقروءة متكافئتان في الفكرة.

## حدود السلوك
- المعرّف بعد # ليس جزءًا من الطلب HTTP؛ المتصفح لا يرسله للخادم. تغيير الجزء المختار يحدث في الواجهة الأم.
- أي عنصر DOM يمكن اختياره بواسطة CSS selector صالح؛ العناصر المتطابقة المتعددة تختزل إلى الأول. يتوقع الاستخدام العادي معرف ID فريدًا.
- الاستبدال ليس innerHTML: العقدة القديمة تُزال، وقد تُفقد حالتها ومستمعو أحداثها والتركيز عليها.
- استجابة فارغة تزيل الهدف؛ الاستجابة 500 قد تعرض HTML الخطأ إذا احتوت العنصر المطلوب، دون معرفة رمز HTTP من htmz.
- التحميل من مصدر آخر يحجب الوصول لوثيقة iframe وفق Same-Origin.
- إرجاع 302 داخل iframe لا يضمن الانتقال في الصفحة الرئيسية.
- عنوان URL في الصفحة الأم لا يتغير تلقائيًا؛ تاريخ التنقل الكامل ليس ميزة مضمونة.
- JavaScript داخل وثيقة iframe الموثوقة يمكن تنفيذه، ما يجعل مصدر HTML حدود أمان أساسية.
- مع CSP صارم يمنع المعالجات inline يتوقف هذا النمط عن العمل؛ يحتاج تصميمًا آخر متوافقًا مع CSP.
