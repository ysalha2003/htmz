# HTMZ Kit v0.1 — مراجعة الإصدار

**التاريخ:** 2026-11-05

**الفرع:** `feat/backend-agnostic-design-system`

**الهدف:** Starter Kit لبناء تطبيقات ويب HTML-first مع اختيار Backend ونظام تصميم موحّد.

## القرار

**PASS لبيئة التطوير والقالب التجريبي — NOT YET PRODUCTION-READY لتطبيق عام يحتوي بيانات أو مستخدمين حقيقيين.**

## ما تم تنفيذه

- واجهة عربية RTL متجاوبة، بملفات HTML/CSS/JavaScript عادية.
- `runtime.js` خارجي للامتثال إلى CSP الصارم، يلتزم بعقد ID واحد في كل استجابة، ويفحص Same-Origin ويضبط تركيز المستخدم.
- Node.js وPython، كل منهما يقدّم المسارات نفسها باستخدام المكتبة القياسية دون اعتماديات تشغيل.
- إجراءات GET/POST واقعية مع CSRF مرتبط بالجلسة، ومعالجة رسائل الأخطاء داخل HTML.
- نظام تصميم من **48 Design Tokens**؛ فحص يراجع 130 مرجعًا للتوكنز، وتباين 6 أزواج ألوان بخط أساس 4.5:1.
- مولّد `tools/create-app.mjs` لإنشاء تطبيق منفصل، مع اسم عرض عربي وتحديث package/lock وملف `START_HERE.md`، ويرفض أي مجلد مقصد موجود.
- معرض مكونات يمكن فتحه على `/design-system.html`.
- اختبار المتصفحات والأدلة في `browser-results.json` مع صور فعلية.

## نتائج الاختبارات

أحدث تشغيل للعقد بين **Node.js/Python × Chromium/Firefox/WebKit**: **108 نجاحًا، 0 فشل**، أي 18 اختبارًا لكل تركيب.

التغطية: صفحة SSR، CSP، تفاصيل المشاريع، التبويبات وإدارة التركيز، GET search، POST وحفظ الملاحظات مع ترميز HTML، CSRF خاطئ وغير ASCII، Origin أجنبي، validation 422، عدم مطابقة العقد، عنوان fragment مفقود أو غير صالح، 404، الهاتف والاتجاه RTL، وعدم وجود استثناء JS غير معالج.

اختبارات Generator: **6 فحوص ناجحة** تشمل الهوية والملفات والتطابق ومنع إعادة استخدام مقصد موجود وإنتاج دليل تشغيل. يتم إنشاء مجلد مؤقت مستقل وإزالته من داخل مساحة المختبر فقط.

الأوامر:

```powershell
cd C:\projects\htmz-lab\fork\starter
npm ci --ignore-scripts
$env:PLAYWRIGHT_BROWSERS_PATH='C:\projects\htmz-lab\browsers'
npm run verify
```

## القيود الحاسمة قبل الإنتاج

هذه **حزمة بداية** وليست إطار مصادقة أو قاعدة بيانات. بيانات المشاريع اصطناعية، وتخزين الملاحظات والجلسات مؤقت في الذاكرة، وتتطلب أنظمة العمل الحقيقية RBAC وPersistence ونسخًا احتياطية وTLS وتجارب استرجاع.

لا تُمرّر HTML غير موثوق إلى iframe من مصدر التطبيق؛ التحقق من ID وOrigin لا يعقّم المحتوى. وتحتاج سياسات CSP وإدارة redirects وhistory والتحمّل للشبكة البطيئة إلى اختبار في التطبيق الذي سيُبنى على هذا القالب.

**الخطوة التالية ذات الأولوية:** تنفيذ Backend Adapter إنتاجي واحد فوق تقنية يختارها المشروع (مثلاً Frappe أو Django أو Go) مع قاعدة بيانات وتسجيل دخول وصلاحيات، دون تغيير HTML Contract أو CSS Design System.

## حجم واجهة Starter (قياس مباشر)

- `public/runtime.js`: **2,365 بايت** غير مضغوط، و**1,132 بايت gzip**.
- `public/design.css`: **8,330 بايت** غير مضغوط، و**2,059 بايت gzip**.
- لا توجد اعتماديات JavaScript وقت التشغيل، كما أثبت `npm ls --omit=dev --depth=0`.
- Playwright موجود فقط لاختبارات التطوير، ولا يدخل في حزمة التطبيق أو تحميل المتصفح.
- لا يعني هذا القياس وحده أن استبدال الأجزاء أسرع من البدائل؛ قياسات الأداء السابقة تخص النواة، وليس حزمة Starter هذه.

## قابلية النقل

اختبارات Chromium تستخدم الآن المحرك المثبّت بواسطة Playwright نفسه بدل الاعتماد على Chrome الموجود بالجهاز. يمكن تجهيز جميع المحركات عبر `npx playwright install chromium firefox webkit`، مع إبقاء المتصفحات المحلية ضمن مجلد المختبر.
